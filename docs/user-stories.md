# 视频转 Markdown CLI：用户故事

状态：P0 命令已实现，真实样本验收进行中。日期：2026-09-07。

配套文档：[技术选型](technical-design.md)、[使用指南](usage.md)。本文规定产品范围和验收条件；实际验证状态见实现指南，不将代码完成等同于全部内容质量验收通过。

实施顺序与验证方法见[实现指南](implementation-guide.md)；项目协作约定见 [AGENTS.md](../AGENTS.md)。

## 1. 产品目标与边界

产品定位是视频到图文 Markdown 的转换与修订工具。面向学习编程、数学及其他理工科课程的个人用户，将本地视频或 Bilibili 缓存整理成可阅读、可核对、可反复修订的文档。

提高学习效率是产品价值，核心工作对象是视频素材和 Markdown 文档。主流程是“导入视频 → 转换初稿 → 核对图文 → 局部修订 → 导出”，交互全部通过 CLI、配置文件和生成的文档完成。AI 负责组织内容、选图、纠错和执行修订指令；按需回看视频是内部质量机制。

- 输入：普通本地视频、已验证格式的 Bilibili 缓存目录，可选 SRT/VTT 字幕。
- 输出：Markdown、原视频截图、来源时间戳、转写和待核对清单。
- 本地保存素材与产物；AI 整理允许使用配置的云端服务，因此“本地优先”不等于“完全离线”。
- 产品范围不包含课程问答、聊天、学习进度管理、跨课知识库、练习与复习调度，这些也不列为后续路线图。CLI 任务进度仅表示转换或修订任务的运行状态。
- 第一阶段不包含前端、账号系统和在线视频下载。每次处理一个视频或一个课时缓存目录，不提供批量课程处理。
- 默认忠实整理原视频，额外解释由用户通过转换或修订要求显式指定，并在输出中标记来源。
- 开发侧可用已保存的证据和草稿离线核对成功结果；该核对只读取既有产物，不改变 P0 的前台转换与 P1 的任务恢复边界。
- 不承诺所有 Bilibili 客户端缓存均可导入，也不承诺从模糊画面恢复精确代码或公式。

## 4. 用户故事与验收标准

### US-01 检查本地素材（P0）

作为学习者，我希望提供一个文件或缓存目录就能看到它是否可处理，以便在运行耗时任务前发现问题。

验收标准：

- `inspect` 展示标题、时长、音视频轨道、分辨率、字幕发现结果和适配器类型。
- 能识别上述真实缓存；不依赖目录编号或文件名后缀猜测实际编码。
- 明确区分“下载元数据显示完成”“媒体可打开”“片段解码成功”“全片验证通过”。
- 媒体打开及轨道探测有部分失败时，不能显示全部成功；状态含义和报错行为见[技术设计](technical-design.md#2-导入与规范时间线)。
- 未知格式、缺少音轨、文件截断等问题给出具体诊断；纯静态画面配有音频属于正常输入。
- `inspect` 不调用付费 AI，不改写源目录；可通过 `--json` 提供机器可读结果。

### US-02 转换单个视频或先处理一个片段（P0）

作为学习者，我希望先处理课程中的一小段，确认效果与成本后再处理整课。

验收标准：

- `convert` 支持 `--start`、`--end`，不指定时处理整课。
- 可以指定 `--profile programming|math|mixed` 和自然语言文档要求，例如“保留推导过程，压缩课程行政说明”。
- 语音识别默认使用阿里云 Qwen，可显式选择本地 CPU/CUDA；来源按真实音频切片区间标注，不宣称句级对齐。已指定的同步字幕可替代云端识别。
- 片段中的全部时间戳映射回原视频，例如从 20 分钟开始的片段不能从 00:00 引用。
- 自动采样支持片段末尾落在两帧之间的情况，保留实际帧时间；边界规则见[技术设计](technical-design.md#2-导入与规范时间线)。
- 越界时间、结束早于开始、输出目录冲突在任务启动前报告；显式 `-f` / `--force` 可删除原输出后重新转换，删除范围和保护规则见[使用指南](usage.md)。
- 云端路径无需本地权重；本地路径按需加载，复用音频切片与并发队列。日志区分解码、模型加载和推理；开发工具测量 CPU、内存、显存和实时率。
- `convert --jobs N` 仅并发语音识别请求，默认 1；转写按原始切片顺序保存，图文整理保持串行。失败或取消后收尾在途请求，不发布成功版本。
- 转换结束后展示 Token meter 与 Estimated 费用，按用户单价区分模型和计费单位；重试用量计入，未知部分明确提示，报告独立保存为 `usage.json`。具体配置见[使用说明](usage.md#token-meter-与估算费用)。
- 前台以进度条显示当前阶段与耗时，详细事件通过 `--verbose` 查看；运行日志保留请求与失败计时，便于分析长任务。中断或失败明确报告，已完成文件不损坏，不承诺 P0 自动续跑。

### US-03 获得可独立阅读的图文讲义（P0）

作为学习者，我希望得到有层次的文字和必要截图，以便脱离连续视频复习主要内容。

验收标准：

- 正文按问题与概念关系组织，使用简短承接、三级子标题和必要的小表格，少量新内容对应短段落；文科区分论点、论据和授课者评价。正文以章节目录、连贯解释和必要截图为主。来源与修订 ID 放在独立 `sources.md`，疑点集中于 `review.md`，不逐段打断阅读。
- 图片无需一一解释；图意清楚或正文已解释时省略图注，必要图注只补充理解要点，不重复抄写图片文字。
- 图文转换和文字修订支持选择 DeepSeek 或 Qwen 3.8 Flash，凭据分别配置；不自动回退。Qwen 显示流式阶段，完成响应经过相同证据校验后生成文档。
- 图片使用相对路径；将整个导出目录复制到其他位置后仍能显示。
- 每张截图在来源索引中保留可读时间戳；每个基于课程内容的实质性笔记块关联来源区间，正文不展示证据清单。
- 无法处理的章节标为未完成，不以少量已完成内容冒充整课结果。
- 使用标准 Markdown；公式采用常见 LaTeX 写法，并注明需要支持数学渲染的阅读器。
- 列表或引用内的完整代码围栏可正常导出和继续修订。

### US-04 保留理工科理解过程（P0）

作为学习编程和数学的用户，我希望笔记保留推导与操作的关键步骤，以便理解结论如何产生。

验收标准：

- 数学段优先组织问题、假设、符号、关键推导、结论和适用条件；不强行填充原课没有的栏目。
- 编程段优先组织目标、代码思路、关键修改、运行结果，以及有教学意义的错误和修复。
- 同一节课允许混合内容类型，不能用同一模板机械处理所有章节。
- 截图覆盖必要的中间状态；鼠标移动、课堂人物移动和重复课件不应生成大量重复插图。
- 看不清的代码、下标或公式保留原图与疑点；整理出的代码不默认声称已运行验证。

P0 使用简单的相邻画面比较：明显切屏时保留切换前画面，并补周期帧和末帧，模型再选图。允许用户指定课件区域。音频在窗口末尾附近的低音量停顿处切分，章节尽量对齐转写边界。接受一定冗余和遗漏，不增加复杂场景分类；复杂布局自动切换和自主补帧归 P1，遗漏可以通过 US-08、US-10 修订。

### US-05 核对来源与 AI 补充（P0）

作为学习者，我希望分辨老师讲了什么、AI 补充了什么，以便判断笔记是否可信。

验收标准：

- 默认正文为原课整理，不重复标注；“AI 补充解释”“待核对”在正文显式区分，完整类别保存在来源索引。
- 时间戳和截图来自已登记证据；不存在的证据 ID 或越界引用无法通过导出校验。
- 在 `review.md` 集中列出模糊公式、转写疑点、缺失步骤和未处理章节，并给出回看时间。
- 不把模型自报置信度当作准确率；证据存在与内容确实支持结论分别检查。
- CLI 产物保证可读时间戳，不保证所有外部 Markdown 阅读器都能一键跳转本地视频。

### US-06 AI 自主按需补查证据（P1）

作为学习者，我希望系统遇到“代入上式”“修改这里”等不完整指代时能回看上下文，以减少错误拼接。

验收标准：

- AI 可请求指定区间的转写、指定时刻截图和截图局部放大。
- 工具返回稳定证据 ID、实际帧时间，补查结果可以用于笔记引用。
- 每章设定补查次数上限；任务设定模型调用预算。达到限制后保留已完成内容，并列出未解决问题。
- 补查不会跳过全课初步扫描或代替章节覆盖检查。
- 回听原音频、自动重转写和原生视频模型补查归入 P1。

P0 边界：转换与修订按预定范围读取转写、候选图和相邻上下文；用户指定时间的抽帧属于 P0。由模型自主决定下一次查什么、反复调用工具的循环属于本故事，不阻塞首版。

### US-07 查询并恢复中断任务（P1）

作为学习者，我希望长课处理被打断后能继续，避免重新转写和重复调用模型。

验收标准：

- 在 P0 前台阶段提示的基础上，支持退出后查询持久化任务状态和章节完成数量。
- Ctrl+C 后已提交的阶段产物可复用；残缺临时文件不能被当作完成结果。
- `status` 展示状态；`resume` 复用仍有效的阶段结果，对输入和配置变化重新计算受影响部分。
- API 超时和限流采用有上限重试；无效配置和认证错误直接报告。
- 记录调用次数和服务返回的 token 用量；没有可靠价格配置时不伪造金额。超时调用可能已计费，不承诺重试零重复费用。

P0 仍保留基本日志、用量记录、有上限的 API 请求重试、取消处理和文件原子提交。P1 增加阶段检查点恢复、配置变化后的依赖失效判断及 `status`、`resume` 命令。

### US-08 局部修订文字并保留手工编辑（P0）

作为用户，我希望对已生成文档指定一个章节或段落，修正术语、调整详略或重写表述，以便逐步获得可用的 Markdown，同时保留手工编辑。

验收标准：

- `revise` 支持稳定章节或段落 ID 和自然语言修改要求，例如“将这里的术语修正为梯度下降”“按原视频补齐这一节推导”“压缩重复讲解”。
- 每次修订落到文档产物中，输出新版本及修改摘要；可以定位修改范围、原因和关联证据。
- 文字修订同步更新目标范围的待核对项，保留范围外疑点和全局提示，所有关联目标在当前版本中存在。
- 以指定版本的当前 Markdown 为基线，原文件保持不变，未选中部分保留原文。目标段已有手工编辑时一并作为修订输入。
- 如果手工编辑破坏了段落定位，报告冲突并仅输出建议片段，不猜测位置、不整篇覆盖。
- 修改文字风格复用已有转写和截图；校正事实时按目标段落的固定来源范围核对证据。P0 不重跑整课，也不要求模型自主补查循环。
- 第一版修订本工具生成且保留工作目录的文档，任意来源 Markdown 的导入修订不在 MVP 范围。

P1 增强：自动处理转写模型、截图策略等配置变化带来的依赖失效，并按受影响范围重算。P0 遇到源素材或提取配置与基线不一致时明确报告，要求重新转换到独立目录，不复用不兼容结果。

### US-10 调整截图并导出可携带版本（P0）

作为用户，我希望替换不清楚或不合适的截图，并带走修订后的 Markdown 和图片，以便在常用编辑器中继续阅读和整理。

验收标准：

- `revise` 可以按图片块 ID 指定替换帧时间。
- 指定确切帧的操作通过媒体工具完成，始终使用完整视频画面，无须模型决定；时间越界明确报错。
- 新截图同步更新实际时间戳和证据关系；修改一个图片块不触发整课转写。
- 每个完成的转换或修订版本均提供 Markdown 与所用图片；版本目录可独立复制，图片引用保持有效。
- 原版与修订版分别保留，用户可直接选择任一版本使用，无需额外开发编辑器或阅读器。

P1 增强：用户用自然语言要求重新选图，由 AI 自主搜索相应视频区间。P0 通过指定时间完成配图修订。

## 5. 使用流程

以下命令在项目目录通过 uv 运行；示例使用完整路径和 PowerShell 单行命令。转换需要所选图文供应商凭据，未提供字幕且使用云端 ASR 时还需 Qwen ASR 凭据；独立检查和精确换图不需要模型凭据。DeepSeek 默认模型为 deepseek-flash；`--provider qwen` 默认使用 qwen3.8-flash 和 DASHSCOPE_API_KEY，完整示例见[使用指南](usage.md)。

```powershell
uv run video-learner inspect "C:\Users\cqqqwq\Videos\bilibili\41301577497" --decode
uv run video-learner convert "C:\Users\cqqqwq\Videos\bilibili\41301577497" --start 00:45:00 --end 00:55:00 --profile mixed --secret "C:\projects\video-learner\secrets\deepseek.secret" --output "C:\projects\video-learner\output\sample"
uv run video-learner revise "C:\projects\video-learner\output\sample" --base r001 --section ch-003 --instruction "按原视频补齐关键步骤，压缩重复说明" --secret "C:\projects\video-learner\secrets\deepseek.secret"
uv run video-learner revise "C:\projects\video-learner\output\sample" --base r002 --block fig-002-002 --frame 00:50:12
```

完整处理复用 `convert`，省略时间范围即可。示例 ID 仅为占位，实际章节和图片块 ID 在 `sources.md` 和正文隐藏锚点中提供；用户可在外部编辑器阅读和手改后运行 `revise`。默认以根目录初稿为修订基线，可用 `--base r002` 指定已有修订版本，避免隐式选择“最新版”。每次修订输出新版本路径。

P1 增加 `status <工作目录>` 与 `resume <工作目录>`；P0 中断后可重新转换到新目录，不将未完成目录当作可恢复任务。

转换的 `--subtitle` 接受显式选择的 SRT/VTT；精确换图通过 `--frame` 指定原视频时间。额外解释通过修改要求和 `--allow-ai-additions` 显式启用。当前精确换图限定在该工作目录的转换时间范围内；其他区间先转换到独立目录。章节目标时长默认 180 秒，分段和采样参数见使用指南。

## 6. MVP 验收素材与质量评估

先建立人工标注的小样本集，再评估整课。至少包含 PPT 讲解、终端或代码操作、数学推导三类片段，每类先选 5–10 分钟。

| 维度 | 检查方式 |
| --- | --- |
| 内容覆盖 | 人工列出关键概念、推导与操作步骤，逐项检查是否保留 |
| 内容正确性 | 核对术语、公式、代码和适用条件，记录需要人工修订的位置 |
| 图文对应 | 检查截图是否支持段落内容、是否清楚、是否存在无意义重复 |
| 引用准确性 | 全量机械校验 ID 和时间边界，人工抽查真实内容对应关系 |
| 修订效果 | 核对指令是否落实、非目标内容是否保留、截图与引用是否同步更新 |
| 完成状态 | 所有计划章节均有完成、失败或待处理状态，不静默遗漏 |
| 使用价值 | 记录每 10 分钟课程所需的人工修订时间，与手工整理比较 |
| 运行成本 | 记录下载、转写、抽帧、模型调用耗时及资源和用量 |

硬性要求：源文件不被修改、引用资源存在、失败显式报告、手改笔记不被默认覆盖、修订版本可独立使用。成功标准围绕初稿可用性、修订效率和转换成本，不引入问答质量或学习管理指标。内容质量和性能阈值在建立基线后确定，不把设计目标写成已测结论。

图文转换可复用已成功章节的完整前缀以争取缓存命中，并设置上下文和请求体预算；具体供应商策略见[技术设计](technical-design.md#4-多模态适配与证据约束)。实际省费以服务返回的缓存用量和估算费用核对，不保证命中或整课一定更便宜。

学习者审阅优先复用已保存的音频转写和图片：区分原课疑点、转写误识、整理错误与跨章衔接问题，逐项记录处理与验证。人工校订可导出独立阅读副本，保留原始证据及基线；不新增课程批处理或恢复任务。
