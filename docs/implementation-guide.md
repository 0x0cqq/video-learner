# 视频转图文讲义 CLI：实现指南

状态：M0–M4 已实现；M5 的人工内容质量与耗时验收仍有缺口，已执行结果见[历史验证记录](validation.md)。

本指南将[用户故事](user-stories.md)和[技术设计](technical-design.md)拆成可验证里程碑，不改变 P0/P1。下面保留实施职责与验收条件，第 8 节记录当前完成状态。开发过程和 ADR 单独保存在[实现笔记](implementation-notes.md)，本指南不记录尝试和回滚。

## 1. 运行环境与验证素材要求

项目使用 Python 3.12 和 uv 锁定依赖，首个验证平台为 Windows。真实视频、转写、图片及凭据保存在仓库外或忽略目录；默认离线测试使用自造媒体和模型替身。实际运行环境、样本和测量结果统一保存在[历史验证记录](validation.md)。本指南不保存 API Key。

语音识别默认由 Qwen 云端执行，也可显式选择本地 CPU/CUDA；音频解码始终在本机。图文整理默认使用 DeepSeek `deepseek-flash`，也可选择 Qwen `qwen3.8-flash`。`inspect` 和精确换图可在没有模型凭据时运行；转换缺少所需凭据会报告配置错误。

## 2. 最小实施边界

P0 完成四条命令：

- `inspect`：识别在线视频 URL/BVID、普通本地视频或单课时缓存，输出诊断信息；URL 先下载，本地素材只读。
- `convert`：单个素材或指定片段，生成图文 Markdown、HTML、PDF、证据及疑点。
- `revise`：指定章节/段落改写、按时间替换完整截图，或独立复审现有证据，输出新版本。
- `export`：默认将现有讲义导出为 Markdown、HTML、PDF，也可只选择部分格式。

P0 同时承担来源校验、基础进度、有界重试、旧文件保护和非目标手改保护。固定证据提取流程服务于转换和修订，模型不自主反复回看。

P1 的断点续跑、SQLite、依赖自动失效、AI 自主补查、自然语言选图、自动布局识别不在首版实现列表。US-09 已移除，不分配里程碑。

## 3. 当前代码组织

源码按职责划分为六个子包，根目录保留 CLI 入口。`exports` 包入口协调三种格式；PDF 排版依赖随常规环境安装；ReportLab 在字体预检时解析字体，Matplotlib 仅在实际排版时加载。

```text
src/video_learner/
  cli.py                  # inspect / convert / revise / export 参数与终端显示
  terminal.py             # 结构化事件到进度条、异常提示及详细模式
  common/
    config.py             # TOML、CLI 覆盖与凭据配置
    concurrency.py        # 有界任务队列、顺序交付与取消收尾
    core.py               # 错误、时间、路径边界
    schemas.py            # 来源、证据、供应商草稿与讲义结构
    usage.py              # 当前转换的 token 汇总与费用估算
    prices.toml           # 估算单价快照，支持用户配置覆盖
    storage.py            # 清单、指纹、原子提交、日志与 OS 文件锁
  workflows/
    ingestion.py          # 三入口准备、目录边界、统一探测、素材发布与失败清理
    conversion.py         # 转换用例编排
    transcription.py      # 共用切片、ASR 并发、取消收尾与证据保存
    versions.py           # 指纹、显式基线、手改标记与修订/复审版本提交
    revision.py           # 显式基线与目标范围修订
    reviewing.py          # 独立复审编排、基线保护与版本提交
    replay.py             # 冻结证据和草稿的只读离线重建
    exporting.py          # 现有版本的只读导出与原子发布
  media/
    download.py           # yt-dlp 单视频适配、最小元数据与脱敏字节进度
    io.py                 # 普通视频/已知缓存、偏移视图、轨道与抽帧
    evidence.py           # 音频窗口、字幕、采样与原课时间映射
    audio.py              # 有界 WAV 编码和低音量停顿切点
  providers/
    base.py               # 单次请求/响应、受控错误、凭据与供应商选择
    deepseek.py           # DeepSeek Responses 协议与用量归一化
    qwen.py               # Qwen 图像输入、思考/正文流分离与用量归一化
    asr.py                # WAV 到完整窗口文本的 Qwen 云端适配
    local_asr.py          # 可选 faster-whisper CPU/CUDA 适配
  notes/
    composition.py        # 章节覆盖、固定证据包、草稿应用、离线语义与缓存校验
    generation.py         # 共用提示词、历史上下文、响应校验与有界修复
    quality.py            # 正文编号泄漏和空标题的确定性检查
    prompts.py            # 生成/复审共用证据、保真、配图和疑点规则
    reviewing.py          # 复审输入、职能边界与纯函数修改应用
    review_prompts.py     # 图文/内容规则及用户自定义要求
    rendering.py          # 渲染、锚点定位、字节替换与图片依赖
  exports/
    __init__.py           # 导出预检、并列适配器、资源复核与共享索引写入
    document.py           # 文档快照、共享语法节点与图片预检
    markdown.py           # 手改字节、锚点与相对图片
    html.py               # 离线单文件、内嵌图片与 MathML
    pdf.py                # 中文字体、分页、表格与公式
tests/
  conftest.py             # 自造音视频与共用已转换讲义夹具
  model_fakes.py          # 确定性草稿、协议响应、流式故障与实际 CLI 调用
  test_pipeline.py        # 多章节 CLI 闭环、供应商切换与失败发布
  test_*.py               # 时间/媒体/证据/转换/供应商/修订/可靠性/用量/性能分析
tools/
  profile_conversion.py  # 既有日志归因与离线本地阶段 profiling
  profile_asr.py         # 指定短片段的 CPU/CUDA ASR 测量
  audit_coverage.py      # 只读对比候选、实际送图与正文配图，定位漏图阶段
  replay_conversion.py   # 无模型调用的转换/文字修订结果核对
  replay_composition.py  # 复用章节证据，显式 --live 时重新请求模型

```

依赖方向：CLI → workflows → media / providers / notes / exports；common 提供共用配置、结构和文件边界。媒体模块不调用 CLI，渲染器不直接调用模型。工作流调用讲义生成层，由生成层确定完整请求并调用供应商；供应商归一化协议响应及失败前已知计量，生成层统一记录用量、逐次核对最终请求预算并校验草稿后交给文档层。上下文与修复策略由生成层统一执行，DeepSeek 和 Qwen 采用相同规则。转写编排通过 WAV 接口调用识别适配器；修订、复审和阅读导出从 versions 模块取得共享版本规则；正式和人工阅读导出共用已知原媒体目录保护。讲义语义校验不依赖工作缓存，各导出入口均执行；登记截图校验实际采用文件，导出完成后复核资源未变。生成会话的响应保存目录由工作流显式传入，初稿发布后随工作目录更新。跨模块使用明确的绝对导入，延迟导入仍保留在原调用点。业务层不依赖 Typer 对象，纯时间转换和文档操作可以独立测试。

模型边界按业务结果保存：转换在整理前记录完整证据状态，每章在请求前记录实际证据包及图片身份、采用后记录草稿；文字修订额外保存当时的手改基线。`notes/composition.py` 根据固定输入应用草稿，`workflows/replay.py` 重建并核对成功版本；这些开发侧记录位于忽略的 `.work/`，不改变 CLI 或可携带版本的使用方式。具体数据和精度见[技术设计](technical-design.md#可复现的业务边界)。

## 4. 公共契约

### 4.1 输入与时间

- 每次输入一个在线视频 URL/BVID、普通本地视频或课时缓存目录，不能递归调度多个课时。yt-dlp 随默认依赖安装，不需要启用开关；素材生命周期由输入准备工作流统一管理，检查与转换复用探测结果，模型和 ASR 配置先于下载预检。完整边界和分 P 行为见[导入契约](technical-design.md#2-导入与规范时间线)。
- `--start`/`--end` 使用原视频时间，范围按 `[start, end)` 解释；显示到秒，内部保留微秒。
- 帧选择先 seek 到不晚于目标的关键帧，再解码至不早于目标的第一帧。自动采样的尾部取帧与精确换图边界见[技术设计](technical-design.md#2-导入与规范时间线)，均保留实际帧时间。
- 使用含已知操作事件的片段核对时间对齐；稀疏抽帧只能作为抽查，不能视为全区间人工标注。
- 音频窗口末尾 20% 内有至少 300 毫秒低音量停顿时提前切分，否则按长度切分。保存所有静音和原始时间映射，切片不重叠，不虚构词句级时间戳。
- ASR 使用 `common/concurrency.py` 的有界顺序交付队列，最多保留 `jobs` 个任务；切片与落盘在调用线程完成。用离线替身验证乱序返回、空文本、调用预算、重试编号及取消收尾；图文串行依赖保持不变。配置见[使用指南](usage.md#asr-并发)。

### 4.2 输出、版本与修订

- `convert -f / --force` 可显式删除原输出后重跑；删除需在预检通过和持锁后执行，路径保护与失败语义见[技术设计](technical-design.md#6-配置提交与失败)。
- 根目录初稿为 r001；后续版本放入 `revisions/r002/` 等目录，编号与父版本关系写入清单。
- 转换默认在 r001 后顺序执行图文、内容复审，全部成功后返回 r002 路径，`--no-review` 仅生成初稿；任一轮失败保留 r001。复审步骤可配置规则和只报告模式，函数接口、状态传递与记录见[技术设计](technical-design.md#独立模型复审)。
- `revise` 默认基线为根目录初稿，`--base` 明确选择修订版，不暗中选择最新版本。
- 每个版本保留结构化讲义、生成快照和当前文件哈希；当前 Markdown 可能有手改，不能只根据旧 `notes.json` 全篇重渲染。
- 新生成的转换与文字修订保存 `CompositionInput` 和已采用的 `Draft`；可用开发工具只读核对当时确定性的证据到文稿链路。历史产物缺少这些记录时仍可阅读；能否修订由原有数据版本契约决定，无法执行该项离线重建。
- 段落和图片块有稳定 ID、起止锚点。定位器必须识别受控锚点，并忽略 fenced code 中的相似字符串；出现歧义时给出冲突，不用宽泛正则猜测范围。
- 正文沿当前原讲义主线组织，将语音解释与对应原图合成一处说明；代码、文档等演示保留必要代表帧，图注默认留空。`sources.md` 集中列出 ID、类别、时间和同步状态，`review.md` 只汇集影响理解的真实未决问题；AI 补充与必要的 uncertain 内容仍显式标记，编辑和听辨说明留在正文之外。
- 写入前再次检查基线当前文件哈希，防止模型请求期间用户继续编辑造成覆盖。新修订与复审包的邻章上下文从当前 Markdown 读取；旧冻结包按其记录的包版本重放。
- 新版本仅替换目标区域。非目标内容按原字节保留，避免无意重排格式、换行或手写说明。
- 如果非目标内容包含用户新增的相对图片，复制其安全可读的本地依赖以维持版本可携带性；遇到缺失资源或目录越界时报告，不能偷偷复制任意路径。
- 改图同步更新图片和证据；图注引用相关旧画面而无法安全改写时列入待核对，不能仅换图就声称图文已一致。
- 原版不变，新版有修改摘要。锚点冲突时只输出诊断/建议片段，不登记一个成功的完整版本。

### 4.3 模型与配置

- 固定证据包包含目标范围内可引用的转写、候选图、相邻只读文本、上一章末尾文本与指令；上下文只帮助衔接，不可引用或重复整理。
- 模型返回正文、块类型、来源类别、证据 ID 和疑点；模型不提供任意本地路径。
- 单块修订的请求 schema 和生成校验同时限定一个同类型块，违反数量或类型约束的响应在调用预算内修复；修订应用按实际目标执行同一校验。请求 schema 按复审职能限制块类型与操作，再校验目标范围、证据存在、时间边界、图片资源和关联。内容是否支持结论、公式和代码是否正确，需对照原课核对。
- 正常测试使用确定性供应商替身，不读取凭据或发网；真实模型请求记录用量、耗时、模型/提示版本和错误类型，不打印敏感 URL 或密钥。
- 默认离线测试复用固定证据和草稿检查章节组织、目标范围替换与生成快照；真实模型内容正确性仍需对照原课单独审阅。
- 配置优先级为 CLI > TOML > 修订基线（修订时）> 默认值，基线中的合法空值保持原义。图文凭据按供应商读取 `DEEPSEEK_API_KEY` / `DASHSCOPE_API_KEY` 或 `--secret` 文件；Qwen ASR 使用 `DASHSCOPE_API_KEY` / `--asr-secret`，凭据不持久化。配置字段见 [config.example.toml](../config.example.toml)。
- `inspect` 和精确换图应可在无 AI Key、无 ASR 权重的情况下运行；大模型组件按需加载，不在 CLI 帮助或探测时下载模型。

## 5. P0 里程碑

里程碑的当前状态见第 8 节。验收必须同时区分确定性功能、真实模型运行和内容质量，不用替身结果替代真实课程产物。

### M0：工程与公共契约

关联：全部 P0 的工程基础。

- 创建 `pyproject.toml`、Python 包入口、uv 锁、最小 pytest/Ruff 配置。
- 先放入该阶段实际需要的依赖，ASR 与供应商依赖在接入时增加并锁定。
- 落实最小 schema、异常分类、时间范围、路径边界和配置规则；避免一次实现所有计划对象。
- 命令入口只注册已实现能力；未实现的转换不得返回伪成功。

完成条件：使用 Python 3.12 安装项目并显示帮助，基础输入/时间/路径行为可离线验证。

### M1：可重复的素材检查

关联：US-01。

- 实现普通视频与已知缓存适配、只读前缀视图和轨道探测；在线入口默认通过 yt-dlp 下载独立素材，经相同媒体检查后使用。
- `inspect` 输出人读和 JSON 结果；明确报告执行了哪个验证层级。
- 先用自造媒体验证前缀不误删、随机定位和不完整文件，再用真实目录做只读抽查。

完成条件：真实样本的轨道、时长和解码结果与独立媒体工具核对一致；没有生成标准化副本到源目录，也没有 AI 请求。媒体文件运行前后哈希保持不变。

### M2：固定证据提取

关联：US-02、US-04、US-05 的基础。

- 支持单素材片段、音频切片、默认 Qwen 和可选本地 CPU/CUDA 识别，仅云端路径校验 ASR 凭据。
- 每 2 秒比较相邻完整画面的缩略图，明显切屏保留前一帧，另保留起始、约每 30 秒和末尾候选；原分辨率保存。接受冗余，不增加场景分类或复杂评分。
- 保存原始转写、实际帧时间、图像关系和指纹；原始转写与校正结果分离，切片来源明确标注为非句级对齐。
- 合法字幕可替代 ASR，时间与覆盖校验独立保留。

完成条件：非零起点片段的转写和帧均回到原课时间；至少核对片段首尾及中间事件，无明显累计错位。记录实际耗时和 ASR 配置，不提前承诺整课性能。该阶段只交付证据，不声称已完成图文转换。

### M3：图文 Markdown 转换

关联：US-02/03/04/05。

- 接入实际可访问的多模态供应商；转写后围绕默认 180 秒目标章长对齐附近转写边界，按连续范围组织，不声称语义话题检测。
- 落实编程、数学、混合内容的整理规则；图片由已登记候选中选择。
- 实现原课整理、显式请求的 AI 补充、疑点及章节完成状态。
- `convert` 的成功版本生成 `notes.md`、`notes.html`、`notes.pdf`、`assets/`、来源、转写、结构化笔记、疑点清单和工作清单；Markdown 与 JSON 是版本数据。
- 基础进度、用量、重试上限、取消提示、输出冲突及原子提交随流程完成，不留到最后补上。阶段完成摘要展示实际处理数量和耗时，口径见[终端显示说明](usage.md#终端进度与详细日志)。
- `convert` 完成或失败后生成 `usage.json` 并显示 token/Estimated 费用，规则与单价配置见[使用说明](usage.md#token-meter-与估算费用)。

完成条件：一个真实片段生成可独立复制的图文文档，资源与引用机械校验通过，人工核对覆盖/正确性并留下记录。供应商未配置时给出配置错误，不把替身输出作为真实课程产物交付。

### M4：可控的文字和图片修订

关联：US-08、US-10。

- 以指定版本、当前文稿和固定范围证据执行文字修订。
- 实现按 ID 和指定帧时间换图，精确操作不调用模型。
- 新版独立保存三种格式，保留原文件、未选中手改内容和版本关系。
- 独立 `export` 复用当前正文和本地图片，三种格式共享快照；遵循[阅读导出契约](technical-design.md#多格式阅读导出)，验证离线可携带性及失败不发布。
- 处理锚点破坏、重复 ID、缺失图片、并发编辑、失配素材和同目录并发写入。

完成条件：对 M3 产物执行一次文字修订和一次换图；原版哈希不变、非目标范围逐字节一致，新版复制到另一目录仍显示全部本地图片。破坏锚点时失败可解释且不产生伪成功版本。

### M5：P0 验收与质量基线

关联：全部 P0。

- 使用 PPT、编程操作、数学推导各 5–10 分钟真实片段建立标注和运行记录。
- 对每段完成转换、人工核对、至少一轮文字或图片修订。
- 小样本行为稳定后再运行约 100 分钟样本，检查全课覆盖、前台进度、内存和总用量。
- 人工修订耗时与手工整理比较；失败和遗漏列出，不用单一“模型评分”替代验收。

完成条件：P0 用户故事逐项有证据；机械检查无缺失引用、越界时间、静默覆盖或伪成功。内容质量有可审查的基线和已知限制。数学素材或真实模型验证缺失时，记录该项未完成，不将整个 P0 标成验收通过。

时间偏移、费用口径、线程取消、路径逃逸、损坏输入和流式错误保留针对具体风险的定位用例。单元与全流程检查不下载权重、不调用云端、不要求真实课程。真实 ASR、供应商和私人样本评估独立执行。检查命令为 `uv run pytest`、`uv run ruff check .`、`uv run ruff format --check .`。

建议每次真实评估在忽略目录 `artifacts/evaluations/` 记录：素材/版本指纹、时间范围、模型与参数、重点标注、遗漏和错误、截图对应、修订要求与结果、人工耗时、机器耗时、资源用量、通过项及未覆盖项。可将脱敏结论写回文档，不提交课程全文、图像或凭据。
